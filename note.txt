# TASK 1 — DOPILOT: Complete Project Initialization

## Project Overview

Build **Dopilot**, an open-source, voice-controlled AI browser agent that operates Chrome and Brave.

Users will visit our website, connect the browser extension, enter their own Groq API key, and instruct the AI to perform browser tasks.

The agent will eventually support voice commands, visual understanding, clicking, typing, scrolling, tab management, and autonomous multi-step workflows.

**This task is ONLY for project initialization, architecture, dependency installation, and validation. Do not implement actual agent functionality yet.**

## 1. Technology Stack

Use:

- **Frontend:** Next.js, TypeScript, Tailwind CSS, Lucide React.
- **Backend:** Node.js, Fastify, TypeScript, Zod.
- **Browser Extension:** Manifest V3, React, TypeScript, Vite, Chrome Extension APIs.
- **AI:** Groq SDK, supporting text and vision-capable models.
- **Agent Framework:** Custom TypeScript agent loop with structured tool calls.
- **MCP:** Official MCP TypeScript SDK v2.
- **Voice:** Browser Web Speech APIs, with graceful compatibility fallbacks.
- **Monorepo:** pnpm workspaces.
- **Testing:** Vitest, ESLint, Prettier.
- **Database:** None initially. Keep the architecture ready for future persistence.

Only use free, open-source dependencies and services with usable free tiers.

## 3. Architecture Requirements

Prepare clean boundaries between:

1. Web interface and user settings.
2. Browser extension and browser interaction.
3. AI model communication.
4. Agent reasoning and execution loop.
5. MCP tool integration.
6. Shared message schemas and validation.

Design the browser extension to operate in both Chrome and Brave.

Use the extension's background service worker for browser commands and content scripts for webpage interaction.

Prepare a browser side panel for future agent conversations.

The web app and extension must have a secure, well-defined communication strategy. Do not assume a normal webpage can directly invoke privileged extension APIs.

Use MCP v2 official packages and prepare the architecture for exposing browser capabilities through MCP-compatible tool interfaces.

Do not require Playwright, PyAutoGUI, Python, or a desktop helper for ordinary browser actions. Use native extension APIs.

## 4. Security Requirements

Prepare for:

- User-provided Groq API keys.
- No hardcoded credentials.
- No API keys committed to Git.
- No transmitting API keys to our own backend unless explicitly required and approved.
- No secrets in logs.
- Permission-based browser access.
- Explicit confirmation for sensitive browser actions.
- Agent stop/cancel controls.
- Execution limits and loop protection.
- Strong validation of AI-generated actions.
- Protection against webpage prompt injection.

Design API-key storage and model requests appropriately for a browser extension, recognizing that client-side keys cannot be completely protected from the device owner or malicious extensions.

Avoid requesting unnecessary browser permissions.
