# TASK 6 — Dopilot: Final Production Readiness Audit

Dopilot is already pushed to GitHub and working locally in Brave.

Your task is to verify and prepare the complete project for production deployment. Do not deploy anything yet.

## 1. Full Production Audit

- Review the complete monorepo.
- Verify frontend, backend, extension, shared packages, MCP, and Groq integration.
- Check production build compatibility.
- Identify missing files, dependencies, environment variables, and configurations.
- Fix actual deployment blockers without unnecessary rewrites.

## 2. Vercel Preparation

- Prepare `apps/web` for Vercel deployment from the existing GitHub monorepo.
- Verify the correct root directory, install command, build command, and output settings.
- Ensure production environment variables are documented.
- Verify HTTPS website-to-extension communication.
- Confirm the frontend does not require the Fastify backend.

## 3. Browser Extension Distribution

- Prepare a production Chrome/Brave extension build.
- Verify Manifest V3 compatibility.
- Verify extension icons, permissions, CSP, and production origins.
- Ensure production extension IDs can be configured correctly.
- Prepare an installable ZIP for manual distribution.
- Verify the ZIP structure and document manual installation.
- Do not publish to the Chrome Web Store.

## 4. Security

- Ensure API keys and credentials are never included in Git or production builds.
- Audit extension permissions and website messaging.
- Verify screenshot, microphone, and Groq privacy controls.
- Check that development URLs are excluded from production.
- Preserve all agent safety and approval restrictions.
- Review third-party license and attribution obligations.
- Identify information needed for a public privacy policy.

## 5. Verification

Run:

- `pnpm build`
- `pnpm typecheck`
- `pnpm lint`
- `pnpm test`
- `pnpm verify:extension`
- `pnpm audit --prod`

Test the production website and extension builds against each other where possible.

Fix genuine failures.

## 6. Restrictions

- Do not deploy to Vercel or Render.
- Do not purchase services.
- Do not publish the extension.
- Do not change the architecture unnecessarily.
- Do not overwrite `note.txt`.
- Do not create a separate Markdown report.
- Do not commit or push without explicit permission.

## 7. Final Response

Provide a concise summary covering:

1. Production readiness: Pass/Fail.
2. Any remaining blockers.
3. Exact Vercel deployment settings.
4. Whether Render is required.
5. Extension ZIP location and installation method.
6. Required production environment variables.
7. Test results.

Prioritize identifying release blockers over cosmetic improvements.
