# TASK 2 — DOPILOT: Frontend, Extension UI & Browser Controls

## Objective

Continue developing the existing Dopilot monorepo.

Build a polished, modern web application and browser-extension side panel. Implement secure Groq API key management and functional browser controls.

The existing monorepo, frontend-extension communication, Fastify backend, and shared packages are already working.

**Do not rebuild the project or change its architecture unnecessarily.**

## 1. Frontend Website

Build a professional, responsive application using Next.js, React, TypeScript, Tailwind CSS, and Lucide icons.

Design requirements:
- Minimal, premium AI-product aesthetic.
- Light and dark themes.
- Smooth, subtle animations.
- Responsive desktop and mobile layouts.
- Clean typography, spacing, and accessible components.
- Avoid generic dashboard templates or excessive gradients.

### Main interface

Include:

1. Dopilot branding and navigation.
2. AI conversation interface with message history.
3. Text command input.
4. Microphone button (UI placeholder only).
5. Extension connection status.
6. Active browser tab information.
7. Agent activity panel (prepared for future tasks).
8. Settings panel.
9. Groq API key configuration.
10. Clear onboarding flow for first-time users.

Display accurate empty states. Do not simulate successful AI responses or browser actions.

## 2. Groq API Key Integration

Implement functional user-provided Groq API key management.

Requirements:

- Users can enter their own Groq API key.
- Save it locally in extension-owned storage, not our backend.
- Never store keys in the website's localStorage or cookies.
- Never log or expose keys in browser messages.
- Provide Save, Remove, and Connection Test actions.
- Show only masked key information.
- Test the key using an inexpensive authenticated Groq API request.
- Handle invalid, expired, and rate-limited keys.
- Support changing keys without reinstalling the extension.
- Never ship a shared API key.

Keep all Groq requests inside the extension.

Use the installed Groq SDK where appropriate, with browser compatibility and security considerations.

Implement configurable text-model selection using supported Groq models. Do not assume a particular model is permanently available.

Do not make any AI requests except those explicitly triggered by the user's connection test.

## 3. Browser Extension Side Panel

Replace the existing placeholder panel with a complete, compact Dopilot interface.

Include:

- Chat-style conversation layout.
- Text command input.
- Microphone button (disabled or marked Coming Soon).
- Current tab display.
- Extension/Groq connection indicators.
- Recent browser actions.
- Settings access.
- Stop button for future agent execution.

The side panel should be usable independently of the website.

Reuse shared UI components where practical, while accommodating the narrow side-panel layout.

## 4. Basic Browser Tools

Implement functional browser controls using Manifest V3 APIs.

Support these explicit commands:

- Open a new tab.
- Open a specified URL.
- Switch between tabs.
- List currently open tabs.
- Reload the current tab.
- Go back.
- Go forward.
- Close a tab, with confirmation.

For this task, implement these through deterministic command parsing or direct UI controls.

**Do not use Groq to interpret natural-language commands yet.**

Examples:

- `new tab`
- `open https://youtube.com`
- `list tabs`
- `reload`
- `go back`

Show actual results or errors in the interface.

Use the minimum necessary browser permissions. Never allow arbitrary scripts or unrestricted privileged actions from website messages.

## 5. Website–Extension Communication

Extend the existing communication bridge.

Requirements:

- Website can display extension connection status.
- Website can send validated browser commands.
- Extension validates every incoming command.
- Extension returns structured success/error responses.
- Requests have unique IDs, timeouts, and cancellation handling.
- Enforce strict origin checks.
- Never send Groq API keys through the bridge.
- Keep communication types in `packages/shared`.
- Ensure the website cannot invoke arbitrary privileged extension APIs.

Handle disconnected extensions gracefully.

## 6. Extension Permissions & Security

- Follow Manifest V3 security requirements.
- Use least-privilege permissions.
- Request optional permissions only when needed.
- Block dangerous URL schemes and restricted pages.
- Validate URL input before navigation.
- Prevent access to internal browser settings and extension pages.
- Require confirmation for destructive actions.
- Never execute AI-generated JavaScript.
- Prepare future safeguards for prompt injection.
- Respect user-initiated tab actions.

Do not request unrestricted website access by default.

## 7. State Management

Create clean state management for:

- Extension connection.
- Groq connection status.
- Browser tabs.
- Conversation UI.
- Settings.
- Browser action results.

Keep architecture ready for future autonomous agent execution.

Do not introduce a database for this task.

## 8. Verification

Implement and run tests covering:

1. Groq API key save/remove and masking.
2. Invalid API key and rate-limit handling.
3. Browser command validation.
4. URL restrictions.
5. Extension message authorization.
6. Tab creation and navigation.
7. Structured action results.

Also manually test the website and extension in Brave if browser access is available.

Do not claim manual tests passed unless verified.
