# TASK 3 — DOPILOT: Build the AI Browser Agent

## Objective

Continue the existing Dopilot monorepo. Task 1 and Task 2 are complete.

Implement a functional Groq-powered AI browser agent that can understand natural-language instructions, observe webpages, reason about actions, execute browser tools, and repeat until a task is completed.

Do not rebuild the existing frontend, extension, or backend.

## 1. Groq AI Integration

Implement real AI inference using the user's saved Groq API key.

Requirements:
- Use the official Groq SDK.
- Discover supported tool-calling models dynamically.
- Select an appropriate default model with reliable tool calling.
- Allow users to change models in settings.
- Handle API errors, rate limits, timeouts, and invalid models.
- Keep API requests inside the extension.
- Never send API keys to Dopilot's backend.
- Avoid unnecessary requests to conserve users' free API quotas.

Ensure the model can call structured browser tools rather than returning unvalidated browser commands.

## 2. Autonomous Agent Loop

Implement a proper agent execution loop inside `packages/agent-core`.

Execution workflow:

1. Receive the user's instruction.
2. Observe the relevant browser state.
3. Send the instruction, observations, and available tools to Groq.
4. Receive the AI's next tool call.
5. Validate the requested action.
6. Execute the browser action.
7. Observe the result.
8. Return the result to the AI.
9. Repeat until completion, user cancellation, or execution limit.

Requirements:
- Maximum 15 actions per task by default.
- Maximum 5 minutes per task.
- Maximum 3 consecutive recoverable failures.
- Prevent infinite loops and repetitive actions.
- Handle multiple tool calls safely.
- Support user cancellation.
- Provide meaningful error messages.
- Detect when the task is complete.
- Pause for approval before sensitive actions.
- Ensure the loop can recover safely from Manifest V3 service-worker suspension.

Do not implement an uncontrolled background agent.

## 3. Browser Observation Tools

Implement webpage understanding using Chrome Extension APIs.

Add the following tools:

- `get_active_tab`
- `get_page_content`
- `get_interactive_elements`
- `get_page_metadata`
- `get_visible_text`
- `get_tabs`

The agent should understand:
- Page title and URL.
- Headings.
- Visible text.
- Buttons.
- Links.
- Input fields.
- Forms.
- Interactive elements.
- Accessible labels and roles.

Use DOM inspection and accessibility-friendly element identification.

Do not collect hidden passwords, cookies, authentication tokens, or unnecessary personal information.

Use explicit user-granted permissions for the websites the agent operates.

Prefer `activeTab` and narrowly scoped optional host permissions rather than unrestricted website access.

## 4. Browser Interaction Tools

Extend `packages/browser-tools`.

Implement:

- `open_tab`
- `navigate`
- `switch_tab`
- `close_tab`
- `reload_tab`
- `go_back`
- `go_forward`
- `click_element`
- `type_text`
- `clear_input`
- `scroll_page`
- `select_option`
- `press_key`
- `wait_for_element`

Requirements:

- Use native browser extension APIs and content scripts.
- Use stable element references generated from observations.
- Revalidate targets before interacting.
- Handle dynamic websites.
- Support scrolling to elements before clicking.
- Verify the result of important actions.
- Report failure if an element cannot be found.
- Handle navigation and page-loading delays.

Do not use arbitrary AI-generated JavaScript, unsafe evaluation, or unrestricted keyboard shortcuts.

## 5. Natural-Language Understanding

Users should be able to type commands such as:

- "Open a new tab."
- "Open YouTube."
- "Search Google for machine learning tutorials."
- "Switch to my GitHub tab."
- "Scroll down."
- "Click the login button."
- "Open my college website."
- "Find the assignments section."
- "Read the question displayed on this page."
- "Click Next."
- "Go back and open another tab."

The AI should interpret the user's intent and choose the appropriate browser tools.

Implement multi-step instruction handling.

Example:

"Open a new tab, go to Wikipedia, search for artificial intelligence, and scroll to the history section."

The agent should execute the necessary actions sequentially, observing the page between steps.

Avoid pretending actions succeeded when they did not.

## 6. MCP Tool Integration

Use the existing `packages/mcp-tools` and official MCP TypeScript SDK v2.

Requirements:

- Expose browser capabilities through MCP-compatible tools.
- Use shared Zod schemas for arguments and responses.
- Connect MCP tool definitions to the same validated browser-tool registry used by the agent.
- Avoid duplicate tool implementations.
- Separate tool registration from execution.
- Ensure permissions and authorization checks apply equally to MCP calls.
- Provide a functional local MCP server entry point for development/testing.
- Do not expose an unauthenticated remote MCP endpoint.

Important: The extension must remain installable without Node.js or a separate MCP server. Use an adapter where required; do not bundle Node-only MCP transports into the browser extension.

Verify that MCP tools are genuinely callable, not merely declared.

Allow users to see what Dopilot is doing.

Keep the current frontend design system and improve it where necessary.

## 8. Conversation Context

Implement lightweight conversation history.

Requirements:

- Support follow-up commands.
- Preserve the current task context.
- Understand references such as "that tab" or "click the next one" when context is available.
- Keep history bounded to prevent excessive token consumption.
- Avoid repeatedly sending entire webpages to Groq.
- Use concise tool results and trimmed page observations.
- Store only the minimum information necessary.

Do not introduce a database.

## 9. Security

Implement strict safety controls.

- No arbitrary AI-generated JavaScript.
- No unrestricted website access.
- No access to browser internal pages.
- No reading password fields or authentication secrets.
- No execution of instructions embedded in webpages as if they came from the user.
- Require approval for form submissions, purchases, account changes, sending messages, file uploads, and destructive actions.
- Treat webpage content as untrusted data.
- Prevent bypassing approval through indirect tool calls.
- Keep permissions restricted to user-authorized websites.
- Provide a prominent emergency Stop button.
- Do not automate CAPTCHA solving or security challenges.
- Never auto-submit graded quizzes or assessments; allow question reading, explanations, and user-reviewed suggestions.

The user must retain control of browser actions.
