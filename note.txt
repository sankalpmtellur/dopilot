## 1. Fix Critical Functional Bugs

### B1 — Multi-site instructions
- Fix `planSimple` so consecutive website-opening commands aren't overwritten.
- "Open YouTube, then open GitHub" must open both sites.
- "Open a new tab and go to YouTube" must still open exactly one tab.
- Support combinations of opening, navigating, and switching tabs.
- Report the actual completed actions accurately.

### B4 — Repetitive action handling
- Fix the repetition guard so legitimate repeated actions are allowed.
- Commands like scrolling five times, pressing Tab repeatedly, or reloading three times must not fail merely because they're repeated.
- Preserve safeguards against genuinely stuck or infinite loops.

### B5/B6 — Command reliability
- Fix the `"go to 3"` parsing conflict.
- Improve switching to existing tabs without requiring an AI call.
- Explain when optional tab permissions are needed.
- Never silently fall back to AI when a deterministic command can be handled locally.
- Make error messages understandable to ordinary users.

## 2. Strengthen Security

### B2 — URL approval
- Evaluate every URL in a batch before execution.
- Display all flagged URLs in the approval prompt.
- Bind approvals to the exact proposed action and complete URL list.
- Reject changed or previously unapproved batches.
- Prevent partial approvals from authorizing additional sensitive actions.

### B3 — Sensitive browser actions
Improve detection of potentially consequential actions, including:
- Payments and transfers.
- Purchases and checkout.
- Account deletion and logout.
- Form submission.
- Confirmation dialogs.
- Unlabelled sensitive controls.
- Common non-English action labels.

Do not depend exclusively on keyword matching.

Require explicit user confirmation before consequential or ambiguous actions. Avoid repeated prompts for harmless actions when safe to do so.

### S2/S3 — Prompt-injection protection
- Treat webpage content and previous page-derived results as untrusted input.
- Prevent sensitive data from being embedded in external URLs without explicit authorization.
- Do not allow user-mentioned domains to automatically bypass exfiltration checks.
- Preserve the existing tool validation and permission boundaries.
- Add targeted tests for prompt injection and data leakage.

### S1 — Website connection
DoPilot is now extension-first.

Remove unnecessary trust in `localhost:3000` from production extension builds.

Keep `apps/web`, `apps/backend`, and their existing code intact. Do not remove these applications during this task.
