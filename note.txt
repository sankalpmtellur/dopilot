# TASK 4 — DOPILOT: Vision AI, Voice Control & Visual Browser Automation

## Objective

Continue the existing Dopilot monorepo. Tasks 1–3 are complete and the agent has been verified with a real Groq API key in Brave.

Implement complete voice interaction and screenshot-based visual understanding.

The goal is to let users speak naturally to Dopilot and have the agent see, understand, and interact with webpages.

Preserve the existing architecture, MCP tools, agent loop, security policies, and frontend design.

## 1. Groq Vision AI

Integrate vision-capable Groq models using the existing user's API key.

Requirements:
- Discover available vision models dynamically, with a configurable fallback.
- Support multimodal image + text requests.
- Capture screenshots of the active browser tab.
- Allow users to ask questions about what is visible.
- Combine screenshot information with existing DOM observations.
- Prefer DOM inspection for ordinary interactions and vision when visual understanding is necessary.
- Compress and resize screenshots appropriately to reduce token consumption.
- Do not repeatedly capture screenshots unnecessarily.
- Handle unsupported models, image limits, timeouts, and API rate limits.

Never claim visual understanding succeeded unless the model actually processed the image.

## 2. Screenshot Capture

Implement browser screenshot tools using supported Chromium extension APIs.

Add:

- `capture_visible_tab`
- `analyze_screenshot`
- `get_visual_page_context`

Requirements:
- Capture only user-authorized tabs.
- Clearly indicate when screenshot capture is occurring.
- Do not capture browser internal pages, unrelated tabs, or private/incognito content.
- Avoid collecting passwords, financial information, authentication secrets, and other sensitive content.
- Require explicit permission before transmitting screenshots to Groq.
- Show an understandable notice that screenshots are processed by the selected AI provider.
- Keep screenshot data temporary; avoid persistent storage unless explicitly requested.
- Validate captured images before processing.

Screenshots must never be sent to Dopilot's backend.

## 3. Visual Browser Interaction

Extend the existing agent to interact with visually identified elements.

Capabilities:
- Identify visible buttons and links.
- Understand icons without text labels.
- Recognize navigation menus.
- Understand basic diagrams, charts, and images.
- Read visually rendered text.
- Understand webpage layouts.
- Assist with elements that DOM inspection cannot adequately describe.

Implement grounded visual targeting.

The agent must not blindly guess coordinates.

Requirements:
- Match visual targets against current DOM elements whenever possible.
- For elements unavailable through DOM targeting, use viewport coordinates only after checking screenshot dimensions, scaling, tab identity, and page state.
- Prefer a validated target over raw coordinates.
- Abort if the page has changed and the target can no longer be verified.
- Never bypass existing approval requirements.
- Never execute arbitrary JavaScript generated by the AI.

Support iframe limitations honestly; do not silently bypass browser security restrictions.

## 4. Voice Recognition

Implement actual microphone functionality.

Users should be able to say:

- "Dopilot, open YouTube."
- "Open a new tab."
- "Search for artificial intelligence."
- "Switch to my GitHub tab."
- "Scroll down."
- "What is on my screen?"
- "Click the Next button."
- "Stop."

Requirements:
- Add microphone permission handling.
- Implement push-to-talk as the default.
- Show listening, processing, and error states.
- Display the recognized transcript before or during processing.
- Submit recognized commands through the existing agent pipeline.
- Support stopping/cancelling recognition.
- Do not record continuously in the background.
- Do not implement always-on wake-word detection yet.

First evaluate browser-native speech recognition.

Because support varies between Chrome and Brave, implement a practical fallback using a Groq-supported speech-to-text API, subject to users' free-tier limits.

Use an explicit user action to start recording and clearly explain when audio is transmitted externally.

Do not store microphone recordings permanently.

Keep text commands fully functional if speech services are unavailable.

## 5. Spoken AI Responses

Implement optional text-to-speech.

Requirements:
- Use browser-native SpeechSynthesis when available.
- Speak short confirmations and final results.
- Provide a mute/unmute setting.
- Allow interruption.
- Never read sensitive webpage content aloud automatically.
- Avoid speaking every intermediate tool result.

Example:

User: "Open YouTube."

Dopilot: "Opening YouTube."

## 6. Agent Integration

Connect voice and vision to the existing agent loop.

The same agent should support:

- Text-only instructions.
- Voice instructions.
- DOM-based page observation.
- Screenshot-based page observation.
- Multi-step browser automation.
- Visual reasoning followed by browser actions.
- Existing MCP tools.

Do not build a separate disconnected voice or vision agent.

The agent should choose the least expensive observation method that can complete the task reliably.

For example:

"Find and click the blue button at the bottom of this page."

The agent should observe the page, use vision if necessary, identify the target, click it, and verify the result.

Maintain the existing execution limits and cancellation mechanisms.

## 7. Frontend & Side Panel

Extend both interfaces.

Add:
- Working microphone button.
- Voice listening animation.
- Live transcript display.
- Voice response controls.
- Vision status indicator.
- Screenshot capture permission prompts.
- Screenshot preview when relevant.
- Clear error messages.
- Settings for voice, vision, and spoken responses.

Maintain a premium, minimal, responsive interface.

Reuse the existing shared UI components.

Do not redesign unrelated sections.

## 8. Safety & Privacy

Preserve all Task 3 safeguards.

Additionally:
- Never capture screenshots without appropriate authorization.
- Never silently enable microphone recording.
- Never persist raw audio or screenshots unnecessarily.
- Never transmit screenshots or audio to our backend.
- Treat visual content and recognized speech as untrusted input where appropriate.
- Keep the agent's existing approval requirements.
- Never automate CAPTCHA solving.
- Never automatically submit graded assessments.
- Require confirmation for sensitive actions.
- Keep an immediately accessible Stop button.

Ensure the website and extension cannot bypass each other's security restrictions.

## 9. Free-Tier Optimization

The project must remain usable without paid subscriptions.

Requirements:
- User-provided Groq API key only.
- Prefer free browser-native capabilities when reliable.
- Avoid duplicate Groq requests.
- Reuse existing DOM observations when possible.
- Compress screenshots.
- Cap screenshot and audio processing per task.
- Display meaningful free-tier rate-limit errors.
- Never automatically switch to paid services.
- Do not install unnecessary heavy dependencies.

## 11. Real Browser Verification

Use Brave for browser testing whenever available.

Test these workflows:

**Test A — Voice navigation**

Say: "Open a new tab and go to Wikipedia."

**Test B — Voice browser actions**

Say: "Switch to my GitHub tab."

**Test C — Vision understanding**

Open a public webpage containing images and ask:

"What can you see on this page?"

**Test D — Visual interaction**

Open a test webpage containing an icon-only button and ask:

"Click the blue button."

**Test E — Multi-step interaction**

Say:

"Open Wikipedia, search for artificial intelligence, and scroll to the history section."

**Test F — Cancellation**

Start a multi-step task and verify that Stop immediately prevents further actions.

Test genuine Groq requests only when the user-provided key is available and access is authorized. Keep inference usage minimal.

Clearly distinguish mocked tests from live model verification.
